# 失败诊断延迟分配复测

2026-11-22，在同一Windows10.0.26200 x64、i7-13620H、Node v24.19.0、MoonBit0.10.18+6c83a7f62环境中，先测量基线提交 `579317576a4a86b615ccfa54ef4eedee201d2713`，再测量优化提交 `d089a83a4be9ae97600ef5b30f5363f4b549cc1e` 对应的运行库。两次使用相同的 `runtime/runtime_bench_test.mbt`，release构建，顺序执行两个后端。

成功选择预期时不再收集不匹配规则的说明数组，也不再寻找诊断渲染器。只有所有规则都不匹配且没有次数/顺序错误时，才按登记顺序整理说明；这个第二遍遍历不调用参数谓词。选择顺序、计数和错误码保持原样。
