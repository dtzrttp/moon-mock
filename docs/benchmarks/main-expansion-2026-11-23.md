# 主分支扩展基准（2026-11-23）

## 运行环境和命令

- Windows `10.0.26200`，x64；Intel Core i7-13620H，16个逻辑处理器。操作系统 WMI 查询被拒绝，平台信息改由 Node.js `os` 模块读取。
- Moon `0.1.20261028`，编译器 `moonc v0.10.18+6c83a7f62`；Node.js `v24.19.0`。
- 分别在 JS 和 Windows native 后端运行 release 基准：

```sh
moon bench runtime matchers generator --target js --release --deny-warn
moon bench runtime matchers generator --target native --release --deny-warn
```

两次命令均以退出码0完成，bench 测试各9/9通过。完整命令结果分别保存在 [JS 原始结果](main-expansion-2026-11-23-js.txt) 和 [native 原始结果](main-expansion-2026-11-23-native.txt)；为通过仓库尾随空白检查，日志只移除了表格对齐用的行尾空格，数值与样本信息未改动。

## 代表性均值

表中为 MoonBit bench 工具报告的 `mean ± 标准差`。生成器样例从一份含32个 trait、每个3个方法的源码中生成1、4或16个 trait。匹配器数组规模为128。历史选择测试在对应容量的缓冲区已填满后测量。

| 项目 | JS | Windows native |
| --- | ---: | ---: |
| 重复解析生成4个 trait | 40.17 ± 0.95 ms | 95.65 ± 0.63 ms |
| 一次准备生成4个 trait | 37.56 ± 3.22 ms | 93.32 ± 9.22 ms |
| 批量生成4个 trait | 40.46 ± 3.15 ms | 89.33 ± 1.60 ms |
| 重复解析生成16个 trait | 158.36 ± 5.11 ms | 388.54 ± 16.45 ms |
| 一次准备生成16个 trait | 148.33 ± 10.79 ms | 351.19 ± 10.92 ms |
| 批量生成16个 trait | 143.25 ± 10.53 ms | 356.28 ± 13.67 ms |
| 无序匹配增广重排（128项） | 195.95 ± 2.13 μs | 146.10 ± 23.63 μs |
| 完整顺序匹配256项中的末项 | 534.39 ± 10.61 ns | 682.17 ± 7.21 ns |
| 有界历史已满时选择一次（容量0） | 15.10 ± 1.33 ns | 145.23 ± 39.00 ns |
| 有界历史已满时选择一次（容量1） | 33.93 ± 2.50 ns | 167.53 ± 0.79 ns |
| 导出1024条历史 JSON | 1.39 ± 0.06 ms | 6.54 ± 0.48 ms |

运行库报告不显示编码后每个值都精确到表格最后一位；表中按原始均值和标准差的有效位数取舍，没有做跨版本换算。基准验证各场景可在两后端完成，不构成生产负载承诺。

## 解读限制

每个样例在同一桌面环境单次运行，编译器和操作系统进程调度、JIT、native 内存分配及电源策略都会影响结果。生成器16项部分每轮只运行一次，native 的生成器预解析样本变异较大。`prepare_sources` 在定时区间内，批量场景也包含生成器批次管理成本。不能据此宣称所有输入都比旧版更快，也没有用这些结果推断其他硬件或后端表现。

历史基准包括无历史容量0作对照；容量1均值呈现几十纳秒的额外记录成本，但不能推广成固定比例。容量1024的 JSON 报告较慢主要是序列化1024项结构的成本，调用历史有明确容量上限。JS 和 native 的计时绝对值不应直接当作跨后端性能排序。
